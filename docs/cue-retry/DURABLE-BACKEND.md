# Durable backend continuation

This supersedes the original browser-local completion boundary. The feature now has actual Express integration, a new unapplied migration and normal frontend access. No optional owner architecture decision is pending; hosted application and release are outside this task's authority.

## Runtime contract

- `GET /api/workout-logs/:id/exercises/:exerciseId/cue-retry` returns `{source_version,can_create,can_recheck,outgoing,incoming}`. The opaque32-character source version is a freshness checksum, never authorization.
- `POST` to the same endpoint takes a UUID `request_id` and `action`: create (`text,source_version`), edit (`cue_id,revision,text,source_version`), cancel (`cue_id,revision`), or verdict (`cue_id,revision,verdict`). Verdict is `pending|fixed|partial|nochange`. Unknown fields/malformed ids/text/verdicts are rejected. Identity comes exclusively from verified `req.user.authUserId`.
- `read_exercise_cues` and `mutate_exercise_cue` repeat current database ownership/auth checks inside the transaction. A client reads their own cues; current coach/admin authors and rechecks. A previously authorized HTTP coach loses access immediately after reassignment. Clients.id is not auth.users.id. Archived profiles/attempts are masked.
- `exercise_attempt_cues` stores source/client/assignment identity, immutable author-name snapshot, text, first linked retry and its prescribed-plan fingerprint, revision, soft cancellation and explicit verdict metadata. `exercise_cue_receipts` is append-only, keyed by provider actor/request UUID, storing the canonical request and original response. Exact replay returns that response; changed-body reuse conflicts. Client/request locks serialize authorized changes; version checks reject stale editors.
- Existing `POST /workout-logs/start` calls `start_workout_log_with_cues`. It locks/reauthorizes the current client, validates actor attribution, delegates **unchanged** `start_workout_log_v2`, then calls `bind_next_exercise_cues` only for a fresh start. The new log/children/link commit together. Link failure rolls the start back. Resume does not retroactively attach a newly authored cue. Existing program and standalone assignment models are retained and locally tested. Legacy/custom attempts without a retained source/assignment identity cannot create a retry cue; no name-based match is invented.
- Text/link/source/author are frozen after linkage. Cue updates never patch source prescriptions, completed workout rows or performed sets. A changed source/assignment/load blocks new linkage until fresh coach review. A changed retry snapshot stays an earlier-plan cue and refuses a verdict; pending is not inferred from completion.
- The existing cue panel now runs in normal API/auth mode for actual logs and in the explicitly labeled isolated IndexedDB scenario when preview is on. Normal mode never loads the browser-local adapter or labels server saves as browser-only. Existing notes, media/demo and workout response behavior remain separate.

The forward migration is `20261027203000_exercise_cue_retry.sql`. Both new tables have RLS enabled with zero policies; browser roles and PUBLIC have no table/RPC access. Only service-role grants are added; receipts cannot update/delete, and business cue deletion is denied. All functions are security invoker with empty search_path. Existing migrations are unchanged.

The installed Supabase CLI failed its help path while trying to write telemetry outside the sandbox. Within explicit repository schema-file authority, the unique new filename was created locally after inventorying prior versions; no hosted CLI command or user setting change was attempted.

**Do not deploy this backend before applying/verifying the migration under separate authority.** Missing schema/RPC is an honest unavailable response, without a silent uncaptured start or browser-fixture fallback. No hosted apply has occurred. PostgREST schema-cache/provider-auth and multi-connection race certification remain unrun environment/release checks, not a reason to stop the authorized engineering.
