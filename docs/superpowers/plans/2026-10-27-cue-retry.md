# Cue → Retry → Recheck implementation plan

**Goal:** Coach-authored actionable cue attached to one completed exercise attempt, shown on the next exact-source attempt, with a coach recheck verdict.
**Architecture:** Extend the existing preview API, workout detail and guided tracker. An opt-in isolated fictional client stores its existing-model rows and cue records in one IndexedDB transaction. Ordinary fixtures and all hosted paths stay unchanged. Production needs a separately reviewed server schema/API implementation.
**Authority:** EXECUTE; inspect/edit/test/scoped commit allowed. No push (automatic CI forbidden), hosted writes, credentials, services, merge or deployment. No agents.
**Spec:** Delegated task in the handoff; text only; preserve completed history and client access.

## Constraints and review focus

- Exact source exercise plus assignment/day identity; no library-name inference.
- One active cue per source attempt; edits/cancel only before linkage; recorded text freezes on linkage.
- Explicit pending/fixed/partial/nochange verdict; coach only, revision-fenced and idempotent.
- Source/assignment changes invalidate unlinked cues; never rewrite performed data.
- Durable acknowledgement only after IndexedDB commit. Failure rolls back local scenario mutation. Concurrent stale writers fail, with reload/retry guidance.
- Local preview roles model boundaries only; they cannot certify hosted security.
